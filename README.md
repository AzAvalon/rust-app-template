# rust-app-template

Template for a Rust application that ships as a container image and a Helm
chart. Create a repository from it with **Use this template**, then rename
things (see [Start a new app](#start-a-new-app)).

## What is inside

| Path                       | What it is                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| `src/main.rs`              | Entry point (`app` binary). Reads `APP_PORT` and starts the server.                                |
| `src/lib.rs`               | The app. Only answers `GET /healthz` for now, with the standard library; unit tests inline.        |
| `tests/`                   | Integration tests: start the `app` binary and call it over TCP. Run with the unit tests.           |
| `Cargo.toml`, `Cargo.lock` | The crate: edition 2024, no dependency, `unsafe` forbidden, clippy pedantic.                       |
| `.cargo/config.toml`       | CPU baselines: x86-64-v3 on amd64, Graviton2+ features on arm64.                                   |
| `.config/nextest.toml`     | cargo-nextest settings and the JUnit report the CI uploads.                                        |
| `Makefile`                 | Local commands, and the targets the CI calls.                                                      |
| `dockerfiles/`             | Dockerfile and bake file of the image.                                                             |
| `chart/`                   | Helm chart: Deployment, Service, ServiceAccount, HPA, PDB, NetworkPolicy, Gateway API.             |
| `.github/workflows/`       | CI, clippy and release, from [AzAvalon/workflows](https://github.com/AzAvalon/workflows).          |

The image is built from the
[AzAvalon base images](https://github.com/AzAvalon/base-images): the
`rust-debian-dev` image compiles the release binary, and the `rust-debian`
image runs it as the `app` user (uid 1001). The CI tests run in the same dev
image.

## Local development

You need a Rust toolchain (1.100 or newer),
[cargo-nextest](https://nexte.st), and for coverage
[cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov). The hooks run
with [prek](https://github.com/j178/prek).

```sh
make test        # run the tests
make coverage    # run the tests with a coverage report
make run         # start the app on http://127.0.0.1:8000/healthz
make clippy      # clippy, every lint as an error
make lint        # run the pre-commit hooks (rustfmt, clippy, ...)
make chart-lint  # lint the chart with chart-testing (ct.yaml, lintconf.yaml)
make docker      # build the image for your machine
```

`make` alone lists every target.

## The Helm chart

`chart/` follows the layout of the Destra service charts and uses the
Bitnami `common` library chart. Every value is listed with its comment in
[chart/README.md](chart/README.md) (generated by helm-docs).

- `settings`: the environment variables of the app (values go through
  `tpl`); `extraEnv` and `extraEnvFrom` for secrets.
- `livenessProbe` / `readinessProbe`: `enabled`, `path` and timings.
- `hpa`: HorizontalPodAutoscaler on CPU, off by default.
- `pdb`: PodDisruptionBudget, created with more than one replica or the HPA.
- `networkPolicy`: off by default. When on, only pods labelled
  `<fullname>-client: "true"`, the ingress controller and `extraIngress`
  get in; `allowExternalEgress: false` limits egress to DNS and
  `extraEgress`.
- `ingress`: Gateway API HTTPRoute (and optionally its own Gateway), off by
  default.

The pod runs as uid 1001 with a read-only root filesystem (`/tmp` is a
small `emptyDir`), no Linux capabilities and the `RuntimeDefault` seccomp
profile. The memory request equals the limit.

## CI and releases

One workflow per concern. On pull requests each one only runs when files it
covers change:

| Workflow         | Runs on                                                                                | What it does                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `pre-commit.yml` | every PR                                                                               | PR title check and pre-commit hooks (rustfmt, clippy, prettier, helm-docs, Renovate config).                 |
| `tests.yml`      | PRs touching `src/`, `tests/`, `Cargo.*`, `.cargo/`, `.config/`, `Makefile`; `develop`; releases | cargo-nextest with llvm-cov in the `rust-debian-dev` container: coverage and JUnit reports.          |
| `clippy.yml`     | pushes to `develop`                                                                    | `clippy --fix` and nightly rustfmt; opens a PR with what they changed.                                       |
| `build-push.yml` | PRs touching the image or the chart; each GitHub release                               | Chart lint and kubeconform, image build and push, chart push, and a deploy of the chart in a kind cluster. |
| `release.yml`    | pushes to `main` (and `x.y.x` branches); by hand on `develop`                          | semantic-release.                                                                                            |
| `pr-cleanup.yml` | PR closed                                                                              | Deletes the PR's images, charts and Actions caches.                                                          |

PR images and charts are pushed as `pr-<number>.<sha>` and
`0.0.0-pr.<number>.<sha>`. semantic-release reads the conventional commit
messages, writes the version into `Cargo.toml`, `Cargo.lock` and the
chart, and creates the GitHub release: a release on `main`, a `-dev`
prerelease on `develop`. That release runs `build-push.yml`, which pushes
`ghcr.io/azavalon/rust-app-template:<version>` (and `latest` from `main`)
and the chart `oci://ghcr.io/azavalon/charts/rust-app-template`.

Renovate keeps the base image, the Rust toolchain of the hooks, the crates,
the actions and the hooks up to date.

The workflows need the variable `CI_APP_CLIENT_ID` and the secret
`CI_APP_PRIVATE_KEY` (the CI GitHub App). Both are set at AzAvalon
organization level. Images are pushed with the job's `GITHUB_TOKEN`.

## Start a new app

Replace `rust-app-template` with the new name in:

- `Cargo.toml` (`name`, `repository`) and `src/main.rs`
  (`rust_app_template::serve`), then run `cargo check` to update
  `Cargo.lock`,
- `chart/Chart.yaml` (`name`) and `chart/values.yaml` (`image.repository`),
  then run the hooks to regenerate `chart/README.md`,
- `dockerfiles/docker-bake.hcl` (`DOCKER_IMAGE`) and `dockerfiles/Dockerfile`
  (the cache mount id),
- `.github/workflows/` (`service-name`, `packages`, `test-id`),
- this README and `SECURITY.md`.

The binary can stay `app`. New GHCR packages start private: make them
public once in the package settings, or the kind deploy in the CI can't
pull the image.
